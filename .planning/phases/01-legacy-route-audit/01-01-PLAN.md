  <action>
Create AUDIT-REPORT.md with the following structure:

1. **Executive Summary**: One paragraph on overall security posture
2. **Route Inventory**: Table of all routes in nextjs-app/app/api/ with endpoint, method, purpose
3. **Vulnerability Assessment**: For each route, document:
   - Timing attack risk (password/token comparison method)
   - Rate limiting status (present/absent)
   - CORS configuration (wildcard vs restricted)
   - Security logging (present/absent)
   - Input validation (method used)
   - Data exposure risk

4. **Severity Classification**:
   - Critical: Timing attacks on password endpoints
   - High: Missing rate limiting on auth endpoints
   - Medium: Wildcard CORS, missing logging
   - Low: Input validation gaps on non-sensitive endpoints

5. **Comparison with Production**: Side-by-side table showing security features in app/api/ vs nextjs-app/app/api/

6. **Remediation Options**:
   - Option A: Remove legacy routes (preferred if unused)
   - Option B: Apply security hardening to match production
   - Option C: Redirect legacy routes to production endpoints

Include line numbers for all findings.
