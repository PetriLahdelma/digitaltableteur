  <action>
Add in-memory rate limiting following the pattern in app/api/contact/route.ts:

1. Add rate limiting constants at module level:
   - RATE_LIMIT_WINDOW_MS = 900_000 (15 minutes)
   - RATE_LIMIT_MAX = 3 (requests per window per IP)
   - buckets = new Map for storing request counts

2. Add rateLimit helper function (same as contact route):
   ```typescript
   function rateLimit(key: string): boolean {
     const now = Date.now();
     const bucket = buckets.get(key);
     if (!bucket || now - bucket.windowStart > RATE_LIMIT_WINDOW_MS) {
       buckets.set(key, { count: 1, windowStart: now });
       return false;
     }
     if (bucket.count >= RATE_LIMIT_MAX) return true;
     bucket.count += 1;
     return false;
   }
   ```

3. Add rate limit check at START of POST handler (before any processing):
   - Check rateLimit(ip)
   - If rate limited, log via SecurityLogger.logRateLimitExceeded
   - Return 429 with Retry-After header

WHY at start: Rate limiting must happen before expensive operations (JSON parsing, DB calls) to prevent resource exhaustion attacks.

WHY 3 requests/15min: Matches contact form limits - a legitimate user won't submit contact info more than 3 times in 15 minutes. Higher would allow spam amplification.
