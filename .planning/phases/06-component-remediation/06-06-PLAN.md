**Identify icon-only buttons:**
The current code already identifies icon-only buttons for styling (line ~409):
```tsx
!children && normalizedIcon ? styles["iconOnly"] : "",
```

**Add validation after the existing deprecation warnings block (around line ~214):**

```tsx
// Icon-only button accessibility warning (development only)
if (process.env.NODE_ENV !== "production") {
  const isIconOnly = !children && (icon || normalizedIcon);
  const hasAccessibleName = !!(accessibleName || accessibleNameRef || tooltip);

  if (isIconOnly && !hasAccessibleName) {
    console.warn(
      "[Button] Icon-only button detected without accessible name. " +
      "Add accessibleName, accessibleNameRef, or tooltip prop for screen reader users. " +
      "Example: <Button icon=\"search\" accessibleName=\"Search\" />"
    );
  }
}
```

**Why warn instead of error:**
- Existing code may have icon-only buttons without names
- Breaking change would cause build failures
- Warning gives developers time to fix without breaking

**Consider adding aria-label fallback from tooltip:**
If tooltip is provided but accessibleName is not, use tooltip as aria-label:

```tsx
const effectiveAriaLabel = accessibleName || (tooltip && !accessibleNameRef ? tooltip : undefined);
```

Then use `effectiveAriaLabel` in commonProps instead of `accessibleName`:
```tsx
"aria-label": effectiveAriaLabel,
```

  <files>nextjs-app/shared/components/Button/Button.tsx</files>
  <action>
Add `aria-busy="true"` when button is in loading state.

**Update commonProps (around line ~404-422):**

```tsx
const commonProps = {
  className: [...],
  "aria-describedby": accessibleDescription,
  "aria-label": effectiveAriaLabel,
  "aria-labelledby": accessibleNameRef,
  "aria-busy": effectiveLoading || undefined,  // ADD THIS
  role: accessibleRole,
  title: tooltip,
};
```

**Why aria-busy:**
- Indicates the button is processing/loading
- Screen readers may announce "busy" state
- Helps users understand why button isn't responding
- `|| undefined` ensures attribute is not rendered when false

**Also consider aria-disabled for loading:**
The button is already disabled during loading (line ~479):
```tsx

```

But for links rendered as buttons (`isLink`), add aria-disabled when loading:
```tsx

  aria-disabled={effectiveDisabled || effectiveLoading}
  aria-busy={effectiveLoading || undefined}
  ...
>
```

Add tests to verify the accessibility improvements.

**Add these test cases:**

```tsx
describe("accessibility", () => {
  describe("icon-only buttons", () => {
    it("should warn in dev mode when icon-only button lacks accessible name", () => {
      const consoleSpy = vi.spyOn(console, "warn").mockImplementation(() => {});
      render(<Button icon="search" />);
      expect(consoleSpy).toHaveBeenCalledWith(
        expect.stringContaining("Icon-only button detected without accessible name")
      );
      consoleSpy.mockRestore();
    });

    it("should not warn when icon-only button has accessibleName", () => {
      const consoleSpy = vi.spyOn(console, "warn").mockImplementation(() => {});
      render(<Button icon="search" accessibleName="Search" />);
      expect(consoleSpy).not.toHaveBeenCalled();
      consoleSpy.mockRestore();
    });

    it("should not warn when icon-only button has tooltip", () => {
      const consoleSpy = vi.spyOn(console, "warn").mockImplementation(() => {});
      render(<Button icon="search" tooltip="Search" />);
      expect(consoleSpy).not.toHaveBeenCalled();
      consoleSpy.mockRestore();
    });

    it("should use tooltip as aria-label when accessibleName is not provided", () => {
      render(<Button icon="search" tooltip="Search the site" />);
      const button = screen.getByRole("button");
      expect(button).toHaveAttribute("aria-label", "Search the site");
    });
  });

  describe("loading state", () => {
    it("should have aria-busy when loading", () => {
      render(<Button isLoading>Submit</Button>);
      const button = screen.getByRole("button");
      expect(button).toHaveAttribute("aria-busy", "true");
    });

    it("should not have aria-busy when not loading", () => {
      render(<Button>Submit</Button>);
      const button = screen.getByRole("button");
      expect(button).not.toHaveAttribute("aria-busy");
    });
  });
});
```

**Note:** If running in production mode, the console.warn tests will not trigger. Ensure test environment is set to development.
