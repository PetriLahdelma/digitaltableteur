<task type="auto">
  <name>Task 1: Add role="status" to Toaster container</name>
  <files>nextjs-app/shared/components/Toaster/Toaster.tsx</files>
  <action>
Add `role="status"` to the container div in ToasterProvider (line 100-107).

Current code:
```tsx
<div
  className={cn(
    "fixed z-50 flex flex-col gap-2 pointer-events-none",
    positionClasses[position]
  )}
  aria-live="polite"
  aria-label="Notifications"
>
```

Change to:
```tsx
<div
  className={cn(
    "fixed z-50 flex flex-col gap-2 pointer-events-none",
    positionClasses[position]
  )}
  role="status"
  aria-live="polite"
  aria-label="Notifications"
>
```

Why `role="status"`:
- `role="status"` is appropriate for "advisory information" that isn't important enough to be an alert
- It implicitly sets `aria-live="polite"` and `aria-atomic="true"` (we keep explicit `aria-live` for clarity)
- Unlike `role="generic"`, `role="status"` supports `aria-label`
- This matches the pattern in research/PATTERNS.md section 12 (Toast/Notification Pattern)

Note: The file is `Toaster.tsx` (not `ToastProvider.tsx` as mentioned in VIOLATIONS.md - that file exists at `/providers/ToastProvider.tsx` but delegates to a separate Toast component and doesn't contain the aria-live container).
