# Product Requirements Document (PRD)

## Project

Digitaltableteur 2026 — “AI-Ready DesignOps Platform & Brand Engine”

## 1. Executive Overview

### Objective

Transform Digitaltableteur.com from a static portfolio into a scalable, commercially viable, AI‑enhanced consultancy platform specializing in Design Systems and AI-driven DesignOps for mid-market SaaS clients.

### Vision

“To be Europe’s most trusted boutique partner for AI-powered Design Systems and DesignOps — delivering production-ready systems in weeks, not months.”

### Mission Statement

Modernize Digitaltableteur’s brand, infrastructure, and market presence through:

- Next-gen architecture (SSR, secure, scalable)
- Clear productized offerings
- Proof-driven storytelling and AI demos
- Consistent growth engine: content, events, and partnerships

- Missing security headers, consent flows, structured data.

## 5. Product Requirements

### 5.1 Functional Requirements

#### Website Platform

- ✅ SSR/ISR with metadata rendering for all pages (Next.js 15+)
- ✅ Static fallback for no-JS browsers
- ✅ Dynamic sitemap generation
- ✅ MDX or CMS backend (Sanity/Contentlayer)
- ✅ Multilingual support (EN/FI)
- ✅ Rich Schema.org metadata (Organization, Article, Service)
- ✅ Consent-based analytics integration (PostHog or Plausible)
- ✅ Secure contact form API (reCAPTCHA + rate limiting)
- ✅ GitHub Actions CI/CD with preflight security scan (OWASP ZAP)

#### Productized Offerings

Each offer page must include:

- Service overview (value prop, process, pricing range)
- Deliverables & timeframe (e.g., 4 weeks for DS Lift-Off)
- CTA: “Book Consultation” or “Download Playbook”
- Testimonials + related case studies
- Structured JSON-LD for service type

#### Case Studies

Each case study includes:

- Problem → Approach → Artifact Gallery → Outcome Metrics → Stack → Quote
- Rich media gallery (images, short videos)
- SEO title and summary
- Category tags (AI, DS, Branding, etc.)

#### AI Demos Portal

- Public micro-app: users select a component to see DS tokens, accessibility, and code
- Rate-limited API + key vault
- Interaction logging for analytics
- Hosted securely (e.g., Vercel Edge Functions)

#### Content Engine

CMS integration for:

- Blog / “Field Notes” articles
- “AI in Design Systems” monthly briefs
- Webinars and events
- Automatic canonical linking to Medium posts
- RSS + newsletter integration (Buttondown or Revue)

#### AI Ops Tools (Internal)

| Tool                  | Description                                            | Data Source                | Output              |
| --------------------- | ------------------------------------------------------ | -------------------------- | ------------------- |
| AI Case Builder       | Generates draft case studies from project repos & Jira | Git commits, screenshots   | Markdown            |
| AI Proposal Assistant | Summarizes meeting notes into proposal templates       | Meeting transcripts        | Markdown / Docx     |
| Design QA Bot         | Checks screenshots for token compliance                | Design tokens, image input | Issue / Slack alert |

### 5.2 Non-Functional Requirements

| Category        | Requirement                                         |
| --------------- | --------------------------------------------------- |
| Security        | HTTPS enforced, HSTS, CSP, SRI, OWASP baseline scan |
| Performance     | LCP < 1.8s, CLS < 0.1, TBT < 150ms                  |
| Accessibility   | WCAG 2.1 AA compliance                              |
| Scalability     | Handle 1000 concurrent sessions                     |
| Maintainability | Decoupled MDX content, Git-based workflow           |
| Localization    | English primary, Finnish secondary                  |
| Observability   | Metrics via Vercel Analytics + Logflare             |
