# Button

**Status:** stable · **Tier:** molecule · **Group:** interaction

Primary action control. Polymorphic: renders a native `<button>` for actions
and an `<a>` for navigation with the same visual contract. Two orthogonal axes
encode meaning: `variant` for visual weight (`primary` / `secondary` /
`tertiary`) and `tone` for semantic colour (`neutral` / `error` / `warning` /
`success` / `info`). Loading and disabled are first-class states with the
matching ARIA wiring; `surface` adapts the colours to dark or brand bands.

## In use

The canonical composition lives in the **Example** story above. The most common
consumers in this repo are the contact-form submit, the hero CTAs in
`patterns/Hero`, and the inline CTAs in `patterns/CTASection`.

Two compositions worth cribbing:

- **Form submit with loading.** Set `loading={pending}`; the component flips
  `aria-busy`, disables the control, and applies the loading style without
  losing focus.
- **Link styled as a button.** Pass `href` and the component renders an `<a>`
  with the same visual treatment. Add `target="_blank"` and it auto-injects
  `rel="noopener noreferrer"`.

Anti-pattern to avoid: an icon-only button without an accessible name. Provide
`accessibleName`, `accessibleNameRef`, or `tooltip`.

## How to use

```tsx
import Button from '@dt/Button';

// Primary action
<Button variant="primary" onClick={onSave}>Save</Button>

// Destructive action (variant x tone)
<Button variant="secondary" tone="error" onClick={onDelete}>Delete</Button>

// Form submit with loading
<Button variant="primary" loading={pending} submits>Send</Button>

// Link styled as a button
<Button href="/contact" variant="tertiary">Get in touch</Button>

// On a dark band
<Button variant="primary" surface="onDark">Book a call</Button>

// Icon-only with an accessible name
<Button icon="search" accessibleName="Search" variant="secondary" />
```

Required consumer wiring: none. Button reads design tokens from `variables.css`
via the theme provider already mounted at the layout level.

Theme & forced-colors: every variant has a forced-colors fallback verified in
the **ForcedColors** story; `surface` swaps colours via static CSS, so it works
inside any layout without consumer plumbing.

## When to use

- Primary or secondary action on a page, form, or modal.
- Submitting a form (`submits` sets `type="submit"`).
- Destructive actions: `tone="error"`, paired with a confirm step.
- Navigation that needs to *feel* like an action; pass `href` to render an
  anchor while keeping the button visual.

## When not to use

- Plain in-text navigation: use **Link**.
- On/off state: use **Switch**.
- Multi-select within a group: use **Checkbox** or **CheckboxGroup**.
- A non-interactive heading or status chip: use **Title** or **Badge**.

## Accessibility

- **Keyboard:** Enter and Space activate (native, not overridden). Tab order
  follows DOM order.
- **Focus:** `focus-visible` only; ring uses
  `var(--focus-ring-color, var(--color-primary))` and survives forced-colors via
  a `Highlight` outline.
- **States:** `aria-busy` is set while `loading` and the control is also
  `disabled`; link mode uses `aria-disabled` since anchors have no disabled
  attribute.
- **Names:** an icon-only button without `accessibleName` / `accessibleNameRef`
  / `tooltip` triggers a dev-mode console warning.
- **Reduced motion:** the press `scale`, the loading pulse, and movement
  transitions are suppressed under `prefers-reduced-motion`; colour transitions
  remain for comprehension.
- **Forced colors:** every variant tested under Chromium
  `emulateMedia({ forcedColors: 'active' })`.
