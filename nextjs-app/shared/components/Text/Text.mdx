# Text

**Status:** beta · **Tier:** atom · **Group:** display

Body and inline typography. Text owns the same size/terminal/line-height
ladder as Title but with a `p`-by-default semantic and a wider polymorphic
surface (`p`, `span`, `div`, `strong`, `em`, `cite`, and the heading tags
for the rare case where you need a heading shape but a body weight).

## In use

Long-form lead-ins, body paragraphs, lede captions, and inline emphasis
inside paragraphs. The **Example** story shows the canonical article body
composition used in the blog routes and `patterns/AboutPageContent`.

Two compositions worth cribbing:

- **Lede paragraph.** `size="l"` with `lineHeight="snug"` directly under a
  hero Title — gives the editorial introduction its weight without
  shrinking the line-length.
- **Inline emphasis.** `<Text as="strong">` inside a paragraph for
  semantic emphasis (renders as `<strong>` and is announced as such by
  screen readers). Avoid `font-weight: bold` overrides on a `Text as="p"`
  for the same effect.

Anti-pattern to avoid: using Text for a heading-level outline marker.
Headings carry navigation semantics (rotor lists, jump-to-heading) that
`Text as="h2"` does not communicate. Use **Title**.

## How to use

```tsx
import Text from '@dt/Text';

// Body paragraph (default)
<Text>We design clarity for ambitious teams.</Text>

// Lede paragraph at larger size, snug line-height
<Text size="l" lineHeight="snug">
  A studio for the people who care about the line where craft and product meet.
</Text>

// Inline emphasis
<p>
  We work with founders who <Text as="strong">ship</Text>.
</p>

// Caption-sized supporting copy
<Text size="xs" terminals="sans">2026 · Helsinki</Text>
```

Required consumer wiring: nothing. The element resolves typography tokens
directly from `variables.css`. The default tag is `p`, so wrapping a Text
inside another paragraph creates invalid HTML — use `as="span"` for inline
positions.

Theme & forced-colors notes: text colour inherits from the surface; light,
dark, and forced-colors modes are covered by surface tokens. The
**ForcedColors** story verifies that the type ramp survives the system
palette unchanged.

## When to use

- Paragraphs of body or descriptive copy.
- Lede paragraphs under a Title hero.
- Inline emphasis inside a paragraph (`as="strong"` or `as="em"`).
- Captions, fine-print, metadata under a Title.

## When not to use

- Section headings — use **Title** so the document outline is honest.
- Form field labels — use **Label**.
- Help text beneath an input — use **HelperText** (carries the right ARIA
  wiring for `aria-describedby`).
- Code snippets — use **CodeSnippet** / **CodeBlockWindow**; their
  monospace family is not part of the Text ladder.

## Accessibility

- **Outline:** Text emits no heading semantics unless `as` is explicitly a
  heading tag. The default `p` is announced as a paragraph by SR rotor
  lists; `as="strong"` and `as="em"` carry semantic emphasis.
- **Reflow:** the type ramp respects user font-size preferences (root
  `font-size` scaling). No fixed `px` overrides on the surface API.
- **Contrast:** colour inherits from the surface; verify in dark mode and
  forced-colors mode in the **ForcedColors** story.
- **Reduced motion:** Text is purely typographic. No motion to suppress.
