# Icon

**Status:** beta · **Tier:** atom · **Group:** display

Phosphor icon wrapper with the project's size ladder, motion affordances,
and the accessibility plumbing that bare SVG insertion forgets. Icon
accepts a Phosphor name (PascalCase like `ShareNetwork`, or a slug like
`share-network`) and resolves the corresponding `@phosphor-icons/react`
component; legacy FontAwesome-style names are aliased so older call sites
keep working without a sweep.

## In use

Used inside Button (start and end slots), Badge, navigation lists, and the
SocialShare row. The **Example** story shows the canonical decorative
inline use; the Compliance and States stories cover semantic and animated
variants.

Two compositions worth cribbing:

- **Decorative inside a labelled control.** `<Icon name="arrow-right" />`
  inside a Button does not need `ariaLabel`; the Button label is the
  accessible name. Icon defaults to `aria-hidden="true"` when no label is
  passed, which is the correct semantic.
- **Standalone interactive icon.** When Icon is the only content of an
  interactive element (an icon-only link), pass `ariaLabel` so screen
  readers announce the purpose. Without it, the control has no name and
  axe will fail.

Anti-pattern to avoid: passing both `ariaLabel` and `decorative` to make
"sure" — the props are mutually exclusive and the component prioritises
`ariaLabel`. Pick one.

## How to use

```tsx
import Icon from '@dt/Icon';

// Decorative (default when no ariaLabel)
<Icon name="check" />

// Named for a standalone control
<Icon name="trash" ariaLabel="Delete" />

// Animated and rotated
<Icon name="spinner-gap" spin />
<Icon name="arrow-up" rotate={90} />

// Legacy FA-style name (auto-aliased)
<Icon name="circle-info" />  // → Phosphor `Info`
```

Required consumer wiring: none. The Phosphor library is bundled and tree-
shakes by import; SSR is supported via `@phosphor-icons/react/ssr`.

Theme & forced-colors notes: in forced-colors mode the SVG follows the
system text colour. Setting `color="…"` overrides only outside forced
colors — the system palette wins.

## When to use

- Decorative glyph inside a labelled control (Button, Tab, Badge).
- The graphic half of a standalone interactive control (passes `ariaLabel`).
- A semantic status indicator paired with text (success / warning / info).
- Motion affordances: `spin` for loading, `pulse` for ambient activity.

## When not to use

- The label *is* the icon and the control has no text — that's an icon-
  only Button; use **Button** with `icon={…}` and `accessibleName` so the
  full button contract (focus, hit-target size, keyboard activation) is
  owned by the right component.
- Branding marks that are not in the Phosphor catalogue — import the SVG
  directly through Next's image pipeline; Icon's contract is the Phosphor
  size and weight ramp.
- A bullet point — list rendering and bullets belong to **List**.

## Accessibility

- **Default semantic:** `aria-hidden="true"` when `ariaLabel` is absent.
  Decorative icons are invisible to screen readers, which is correct when
  the surrounding text already names the control.
- **Named semantic:** passing `ariaLabel` adds `role="img"` and the label
  becomes the accessible name. The SVG itself stays `aria-hidden` —
  Phosphor's nested `<title>` was unreliable for label resolution.
- **Motion:** `spin` and `pulse` honour `prefers-reduced-motion: reduce`.
  When the user has motion suppressed the animation does not run; the
  icon stays at rest.
- **Forced colors:** the SVG follows the system text colour; explicit
  `color` overrides are dropped in forced-colors mode.
