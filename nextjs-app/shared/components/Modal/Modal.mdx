# Modal

**Status:** beta · **Tier:** molecule · **Group:** overlay

Focus-trapped dialog rendered through a portal to `document.body`.
Modal applies the `inert` attribute to the page's main content while
open so focus cannot escape, restores focus to the previously active
element on close, and dismisses on Escape or backdrop click. Severity
variants flip the role from `dialog` to `alertdialog` and inject a
semantic icon in the header.

## In use

The contact form uses Modal for the success acknowledgement; the
newsletter waitlist uses it for the post-signup confirmation. The CV
download flow uses Modal for the password prompt. The chat widget
uses Modal for the email composition review step.

Three compositions worth cribbing:

- **Confirmation modal.** Severity `success` or `info` with a title,
  short body, and the default OK button. The component supplies the
  button when `footer` is undefined.
- **Custom footer.** Pass a `footer` node for two actions or a primary
  + secondary pair (Save / Cancel). The default OK is replaced
  entirely.
- **Loading state.** `isLoading={true}` shows a spinner in the body
  area and suppresses the default OK button. Useful for "submitting"
  states where the user can't act until the work completes.

Anti-pattern to avoid: using Modal as a side-panel substitute. Modals
are interruptions — they should be reserved for content the user must
respond to. For a settings drawer that the user opens at will, use a
non-modal panel pattern.

## How to use

```tsx
import Modal from '@dt/Modal';

// Confirmation
<Modal
  isOpen={isConfirmOpen}
  onClose={() => setIsConfirmOpen(false)}
  title={t('contactSubmitSuccessTitle')}
  severity="success"
>
  <p>{t('contactSubmitSuccessBody')}</p>
</Modal>

// Destructive action (alertdialog role)
<Modal
  isOpen={isConfirmDelete}
  onClose={onCancelDelete}
  title={t('confirmDeleteTitle')}
  severity="warning"
  footer={
    <>
      <Button variant="tertiary" onClick={onCancelDelete}>Cancel</Button>
      <Button variant="error" onClick={onConfirmDelete}>Delete</Button>
    </>
  }
>
  {t('confirmDeleteBody')}
</Modal>

// Loading
<Modal isOpen={isSubmitting} isLoading title={t('submitting')} />
```

Required consumer wiring: the parent must own `isOpen` state and
provide `onClose`. The component handles focus trap, focus restore,
Escape, and backdrop click internally.

Theme & forced-colors notes: the overlay uses an `rgba` black at 50%
opacity in light mode and 65% in dark mode. Forced-colors substitutes
`Canvas` and adds a `SystemHighlight` 2px border on the modal so the
edge is visible without the dim layer.

## When to use

- Confirmation of a destructive action (`severity="warning"` with
  `Cancel` / `Confirm` footer).
- Post-submit success acknowledgement that requires no further input.
- A small task that must complete before the user continues (password
  prompt, email review).
- An alert the user must dismiss before continuing
  (`severity="error"` with `alertdialog` role).

## When not to use

- A side panel for adjustable settings — use a non-modal drawer.
- A toast-style confirmation — use **Toast**.
- A multi-step flow that needs URL persistence — use a dedicated
  route instead; modal state is ephemeral.
- A tooltip — use a tooltip primitive (planned).

## Accessibility

- **Roles:** `dialog` by default; `alertdialog` when `severity` is
  `error` or `warning`. The component does **not** add `aria-live`
  because both roles announce on open (adding `aria-live` causes
  double-announcement on most AT combinations).
- **Focus management:** on open, the component stores the currently
  active element, applies `inert` to the page's main content, and
  focuses the first focusable element inside the modal (or the modal
  itself). On close, focus returns to the stored element.
- **Escape:** the wrapper handles Escape via `onKeyDown` and calls
  `onClose`. The component does not trap Tab itself — the `inert`
  attribute on the main content does that for us, which is the
  modern browser-supported way.
- **Backdrop click:** clicking the overlay (not the modal surface)
  calls `onClose`. Clicks that originate inside the modal don't bubble
  to the overlay handler (`e.target === e.currentTarget` guard).
- **Labelling:** the title element (`<Title id={titleId}>`) is the
  `aria-labelledby` target. If no title is passed, the component
  falls back to `aria-label="Dialog"` — pass a title when possible.

## Promotion notes

- Stable promotion blockers: AT-tree snapshots for each severity,
  real-browser forced-colors run, focus-restoration regression test,
  and documented production consumers (contact form success modal is
  the highest-traffic one).
- Known debt: the focus-trap relies on `inert` for browser support.
  Older browsers (pre-2023 Safari) fall back to allowing Tab to escape
  the modal. The fallback is acceptable for our supported browser
  matrix; flagged for a JS-based trap if support requirements widen.
