# Toast

**Status:** beta · **Tier:** molecule · **Group:** feedback

Transient notification that surfaces, announces, and auto-dismisses.
Toast is the right primitive for "confirmation after action" — settings
saved, message sent, copied to clipboard. Four tone levels match
AlertBanner (`info` / `success` / `warning` / `error`); six positions
cover the corners and top / bottom centre.

The `ToastProvider` already mounted at the app root owns the live
region; this component is the visual + accessibility implementation
that the provider renders on demand. Most consumers should call
`showToast()` rather than mounting `<Toast />` directly.

## In use

The `useToast()` hook is the entry point used by SiteHeader (theme +
language toggle confirmations), the contact form (submit success), the
share buttons (copy to clipboard), and the cookie consent flow. The
toast root is mounted once by `ToastProvider` at the app shell level.

One composition worth cribbing:

- **Provider-driven.** Call `useToast()` to get `{ showToast }`, then
  call `showToast(message, duration)` from any component. The provider
  handles mount, position, and dismissal.

Anti-pattern to avoid: mounting two `<Toast />` instances side by side.
The auto-dismiss timer is per instance, but the AT live region is
shared — you'll get double-announcement and a stale visual.

## How to use

```tsx
import Toast from '@dt/Toast';
import { useToast } from '@/providers/ToastProvider';

// Direct (rare — the provider does this for you)
<Toast
  open
  tone="success"
  message="Settings saved"
  position="bottom-center"
  duration={3000}
  onClose={() => setShown(false)}
/>

// Recommended — via the provider hook
const { showToast } = useToast();
showToast(t('contactSubmitSuccess'), 4000);
```

Required consumer wiring: mount `<ToastProvider>` at the app shell
(already done in `app/layout.tsx`). Consumers then use the hook.

Theme & forced-colors notes: tone styling uses
`--color-<tone>-surface` for the toast surface and
`--color-<tone>-text` for the message. Forced-colors collapses to
the system palette and keeps the leading icon (filled Phosphor glyph)
as the sole signal.

## When to use

- Confirmation immediately after a user-initiated action.
- Non-blocking error feedback ("Couldn't reach the server, retrying").
- Status updates the user can ignore without harm.

## When not to use

- Persistent status — use **AlertBanner**.
- Field-level validation errors — use **HelperText** with `state="error"`.
- A confirmation that requires acknowledgement ("Delete this thing?") —
  use **Modal** with `severity="warning"`.
- A counter or score update — use a live region you control; Toast is
  for events, not metrics.

## Accessibility

- **Roles:** `role="status"` with `aria-live="polite"` for `info` /
  `success`; `role="alert"` with `aria-live="assertive"` for `warning` /
  `error`. `aria-atomic="true"` ensures the full message is read on
  every announcement, not just the diff.
- **Live region:** the toast root inside `ToastProvider` is a single
  shared live region; rendering an empty message string between
  announcements gives the AT a beat to reset.
- **Auto-dismiss:** the `duration` prop (default 3000 ms) starts a
  `setTimeout` on mount; on unmount or `open=false` the timer is
  cleared. The user cannot pause auto-dismiss — for long-form
  messages, use **AlertBanner** instead.
- **Reduced motion:** the slide-in animation is suppressed under
  `prefers-reduced-motion: reduce`. The toast simply appears in place.
- **Focus:** Toast does not steal focus. The user's caret stays in the
  field or button that triggered the toast.

## Promotion notes

- Stable promotion blockers: AT-tree snapshots for each tone,
  forced-colors run, and a documented production consumer (the
  ToastProvider is the canonical consumer; the contact form is the
  shipping use).
- Known debt: there is no built-in "undo" affordance. A future
  `action={{ label, onClick }}` slot is on the backlog for actions
  like "undo delete".
