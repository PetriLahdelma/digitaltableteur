# Avatar

**Status:** beta · **Tier:** atom · **Group:** display

Profile representation: image, initials fallback, optional link, and an
optional in-place dropdown menu. Avatar resolves an image source from a
plain URL, a Next `StaticImageData`, or an `{ default }` import shape; if
the image fails or is omitted, it falls back to initials derived from
`name`. When `menuItems` are passed, the component renders as a button
that opens a positioned menu and handles outside-click + keyboard close.

## In use

Site header chrome (`patterns/SiteHeader` shows the menu mode in chat
authenticated state), team rosters on the About page, and any author
attribution surface. The **Example** story mirrors the SiteHeader
composition.

Two compositions worth cribbing:

- **Linked avatar (no menu).** Pass `destinationUrl` and `clickable`; the
  component renders as an anchor with the right `rel`/`target` defaults.
  No JavaScript menu plumbing — just a clickable visual.
- **Menu trigger.** Pass `menuItems` for an in-place dropdown. The
  trigger gets a proper `aria-haspopup` + `aria-expanded` contract and
  the menu repositions on viewport changes so it never clips offscreen.

Anti-pattern to avoid: rendering a fallback image as a `<img>` next to the
Avatar instead of letting the component resolve initials. The internal
fallback path is part of the contract; using it externally re-introduces
the failure modes Avatar is there to prevent.

## How to use

```tsx
import Avatar from '@dt/Avatar';

// Basic avatar with image and fallback initials
<Avatar name="Petri Lahdelma" imageUrl="/avatar.jpg" />

// Initials-only (no image)
<Avatar name="Petri Lahdelma" variant="initials" />

// Linked avatar
<Avatar name="Petri" imageUrl="/avatar.jpg" clickable destinationUrl="/about" />

// Menu trigger
<Avatar
  name="Petri"
  imageUrl="/avatar.jpg"
  menuLabel="Open profile menu"
  menuItems={[
    { label: 'Profile', href: '/profile' },
    { label: 'Sign out', onSelect: handleSignOut },
  ]}
/>
```

Required consumer wiring: the I18n provider must be mounted (the menu
label, image alt, and initials fallback all flow through `react-i18next`).
The project's layouts already mount this.

Theme & forced-colors notes: initials fallback inherits text colour from
the surface; image mode is unaffected by themes. Forced-colors mode uses
the system's `ButtonText` on the menu trigger and `Canvas` on the menu
surface.

## When to use

- Profile or author affordance next to a name (header, comment, team list).
- An in-place menu trigger that needs the visual weight of an avatar.
- A linked profile entry point on a marketing surface.

## When not to use

- Decorative imagery — use a plain `<img>` or Next `Image`. Avatar carries
  semantic weight (profile, person, identity).
- A button with a logo — use **Button** with a logo `icon`. Avatar's
  initials/image fallback is profile-shaped, not brand-shaped.
- A user-list row primary control — use **List** with an Avatar inside
  the item, not a bare Avatar.

## Accessibility

- **Image alt:** when `imageUrl` is provided, `alt` defaults to `name`. If
  `name` is missing, the image alt falls back to an empty string and the
  avatar is treated as decorative.
- **Initials:** when no image renders, the visible initials are also the
  accessible name (no extra ARIA needed — visible text is the contract).
- **Menu trigger:** the button carries `aria-haspopup="menu"` and toggles
  `aria-expanded`. The menu's first item receives focus when opened with
  the keyboard; arrow keys move between items; `Escape` closes and
  returns focus to the trigger.
- **Link mode:** when `clickable` + `destinationUrl` are set the element
  becomes an `<a>` with the link-mode ARIA contract; external URLs add
  `rel="noopener noreferrer"`.
- **Reduced motion:** the menu opens with a CSS transition that respects
  `prefers-reduced-motion: reduce`.
