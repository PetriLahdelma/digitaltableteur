# Badge

**Status:** stable · **Tier:** atom · **Group:** display

Compact status label. Badge carries a short string of meaning — a state, a
count, a tag — with two orthogonal axes: `variant` for visual weight
(`primary` filled, `secondary` outlined) and `tone` for semantic colour
(`neutral` / `error` / `warning` / `success` / `info`). A matching status icon
is auto-resolved for non-neutral tones. Badges can be removable (built-in
dismiss affordance) or live (`role="status"` for screen-reader announcements).

## In use

Used inside card headers (a status tag next to the title), as filter chips on
the work index, and as counters on chat-style surfaces. The **Example** story
shows the canonical tone + icon composition.

Two compositions worth cribbing:

- **Filter chip with remove.** `removable` plus `onRemove` gives a built-in
  dismiss; the close button is an internal Button atom with the right hit-target
  and a translated `accessibleName`.
- **Live counter.** `role="status"` adds `aria-live="polite"` so screen readers
  announce updates without yanking focus.

Anti-pattern to avoid: shipping a static badge with `role="status"` — the
live-region churn is wasted when the content never changes.

## How to use

```tsx
import Badge from '@dt/Badge';

// Static status tag
<Badge tone="success">Completed</Badge>

// Outlined, secondary weight
<Badge variant="secondary" tone="info">Beta</Badge>

// Removable filter chip
<Badge removable onRemove={() => removeFilter('Helsinki')}>Helsinki</Badge>

// Live count
<Badge role="status" tone="info">{unreadCount} new</Badge>

// Custom icon
<Badge tone="warning" icon={<Icon name="warning-circle" />}>Action required</Badge>
```

Required consumer wiring: none. Translations route through the project's
`react-i18next` instance, so the close button label localises automatically.

Theme & forced-colors: the **ForcedColors** story verifies each tone survives
the system palette. Filled (`primary`) status icons swap to high-contrast white;
outlined (`secondary`) tones use semantic colours that pass AA on both themes.

## When to use

- A short status or category label next to a heading, list item, or row.
- A filter chip the user can remove.
- A live counter (unread, queue length) that updates at runtime.

## When not to use

- A standalone interactive action — use **Button**.
- An inline status phrase in body copy — use `<Text as="strong">` with the right
  colour rather than wrapping a phrase in a Badge.
- A toggle or selection state — use **Switch** or **Checkbox**; Badge owns no
  pressed/checked state.

## Accessibility

- **Default semantic:** a plain `<span>` with no role; the surrounding heading
  or text carries the meaning.
- **Live semantic:** `role="status"` adds `aria-live="polite"`. Use sparingly.
- **Removable affordance:** the close button is a Button atom with a translated
  `accessibleName` (`t("badgeRemove")`); focus moves cleanly on remove.
- **Tone contrast:** filled (`primary`) icons get an explicit high-contrast
  colour pair; outlined (`secondary`) tones inherit the semantic palette.
- **Reduced motion:** the badge is static; the removable hover/press is
  CSS-only and respects `prefers-reduced-motion: reduce`.
