# Breadcrumb

**Status:** beta · **Tier:** molecule · **Group:** navigation

Hierarchical trail showing where the user is inside the site. Renders a
`<nav aria-label="Breadcrumb">` wrapping an `<ol>` of items; each item is
a `Link` *except* the last, which is a non-interactive `<span>` because
linking the user to the page they are already on is a usability dead
end. Pass an `items` array of `{ label, href? }`; omitting `href` on
intermediate items renders them as static spans (rare, but supported).

## In use

Used on every `/work/<slug>` case study, every `/blog/<slug>` article,
and the legal pages (`/imprint`, `/privacy-policy`). The breadcrumb is
the first navigation primitive announced on these pages, which is why
the `aria-label` is configurable per page (default: `"Breadcrumb"`,
translated per locale).

One composition worth cribbing:

- **Two-level trail.** `Home / Work / Acme rebrand` — pass three items
  with the first two carrying `href`. The component auto-marks the last
  as current and skips the separator after it.

Anti-pattern to avoid: putting a clickable last item. Even if the
`href` matches the current path, `aria-current="page"` makes the link
behave as a no-op for screen reader users, which is worse than just
rendering text. The component already enforces this — the prop is
honoured but suppressed on the last item.

## How to use

```tsx
import Breadcrumb from '@dt/Breadcrumb';

<Breadcrumb
  items={[
    { label: 'Home', href: '/' },
    { label: 'Work', href: '/work' },
    { label: 'Acme rebrand' }, // current — no href
  ]}
/>

// Translated label
<Breadcrumb
  aria-label={t('breadcrumb.label')}
  items={crumbs}
/>
```

Required consumer wiring: nothing. The component renders `null` when
`items` is empty, so it's safe to call with a derived list that may be
empty for the home page.

Theme & forced-colors notes: the separator (`/`) is a literal slash
rendered as `aria-hidden` text. Forced-colors keeps the slash visible
without affecting the link contract.

## When to use

- A page nested at least two levels deep where the user benefits from a
  "back to parent" path.
- An article, case study, or detail page that lives inside a category.
- Search-result detail pages — breadcrumb helps the user understand
  where they landed after a SERP click.

## When not to use

- The home page or any first-level page — there's no trail to show.
- Modal or drawer content — surface dismissal as a close button, not a
  breadcrumb.
- Step-by-step flows (checkout, onboarding) — use a stepper instead;
  breadcrumb implies free navigation, which breaks step constraints.

## Accessibility

- **Roles:** `<nav aria-label="Breadcrumb">` wraps an ordered list; AT
  users hear "Breadcrumb, list, N items" and can jump landmarks to
  reach it. The last item is a plain `<span>` so screen readers
  announce it as text, not a navigable link.
- **Current page:** the trailing item carries `className="current"` for
  styling and no link affordance for AT users. (The `aria-current="page"`
  attribute on the link is intentionally not used because the current
  item is rendered as a span, not a link.)
- **Keyboard:** Tab moves through each link in order. The last item is
  not focusable, which matches user expectation for "you are here".
- **Localisation:** the wrapper `aria-label` must be translated — pass
  `aria-label={t('breadcrumb.label')}` per locale. The default English
  literal is for development convenience only.

## Promotion notes

- Stable promotion blockers: AT-tree snapshots for the three required
  stories (default / long trail / single-item), real-browser
  forced-colors run, and documented production consumers (case studies
  and articles already use it).
- Known debt: there is no built-in truncation. On narrow viewports a
  long trail wraps to two lines. A future `maxItems={3}` prop with
  middle-collapse (`Home / … / Acme rebrand`) is on the backlog.
