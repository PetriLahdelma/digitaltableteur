# Checkbox

**Status:** beta · **Tier:** atom · **Group:** form

Single binary control with optional label, indeterminate state, and the
controlled/uncontrolled distinction made explicit via `checked` vs
`defaultChecked`. Indeterminate is a true tri-state for "some children
selected, not all"; the visual class is wired separately from the native
`indeterminate` property so styling and SR semantics stay in sync.

## In use

Used inside the contact form for terms-of-service agreement, in
`CheckboxGroup` for multi-select lists, and as a child of file-upload
multi-selection. The **Example** story shows the labelled controlled
form-field composition.

Two compositions worth cribbing:

- **Controlled with label.** Pass `checked` + `onCheckedChange` and let
  the parent own the state. The internal label uses the project's Label
  atom and the right `htmlFor`/`id` plumbing happens automatically when
  you pass `id`.
- **Group parent.** Set `indeterminate` on a parent checkbox when only
  some children in a group are selected. The native `indeterminate`
  property toggles independently of `checked` so the visual matches the
  semantic.

Controlled state uses the unprefixed `checked` / `indeterminate` props —
the platinum API contract — paired with `onCheckedChange`. There are no
`is*`-prefixed aliases.

## How to use

```tsx
import Checkbox from '@dt/Checkbox';

// Controlled
<Checkbox
  id="terms"
  label="I agree to the terms"
  checked={agreed}
  onCheckedChange={setAgreed}
/>

// Uncontrolled with initial state
<Checkbox id="news" label="Send me updates" defaultChecked />

// Indeterminate (parent of a group)
<Checkbox
  id="select-all"
  label="Select all"
  indeterminate
  onCheckedChange={onSelectAll}
/>

// No visible label (use label for SR name)
<Checkbox label="Toggle row" showLabel={false} />
```

Required consumer wiring: when `id` is omitted the component generates
one; consumers wiring `aria-describedby` from a HelperText must pass `id`
explicitly. The internal Label uses `htmlFor` automatically.

Theme & forced-colors notes: the check glyph uses `--color-on-primary`;
the unchecked surface uses `--color-surface-2`. Forced-colors mode swaps
to the system's `Highlight` for the focus ring and `ButtonText` for the
check glyph.

## When to use

- A single yes/no toggle in a form (terms of service, opt-in).
- A child checkbox inside CheckboxGroup for multi-select lists.
- A parent indeterminate checkbox representing partial selection of a
  child group.

## When not to use

- An on/off switch for a setting — use **Switch**. The visual and ARIA
  contract differ (Switch is a `role="switch"`, Checkbox is a checkbox).
- A radio-style choose-one — use **Radio** / **RadioGroup**.
- A truly tri-state choice surfaced to the user (yes/no/maybe) —
  indeterminate is for "partial selection", not "three options".

## Accessibility

- **Native control:** uses a real `<input type="checkbox">` so all
  keyboard, focus, and SR behaviour is the platform's. Space toggles.
- **Label:** the visible label is wired via `htmlFor`. Passing
  `showLabel={false}` keeps the SR name but visually hides the text via
  the project's `srOnly` class.
- **Indeterminate:** the native `indeterminate` property is set
  imperatively on the input element (it's not a serialisable attribute).
  Screen readers announce "mixed" for the tri-state.
- **Disabled:** the native `disabled` attribute is set; the underlying
  control is not focusable and click handlers do not fire.
- **Reduced motion:** the check glyph transition is suppressed under
  `prefers-reduced-motion: reduce`.
