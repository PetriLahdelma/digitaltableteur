# Title

**Status:** beta · **Tier:** atom · **Group:** display

Page and section headings. Title encodes typographic scale (7 sizes,
XXS → XXL) and terminal family (`serif` for editorial weight, `sans` for
product chrome) without forcing the consumer to think about the underlying
`h1`–`h6` element. The semantic tag is chosen with `as` (explicit) or
`level` (1–6); the visual treatment is independent of either.

## In use

Hero headlines on marketing surfaces, section titles on long-form pages,
form group labels in flows. The **Example** story shows the canonical
hero composition used in `patterns/Hero` and `patterns/HighlightSection`.

Two compositions worth cribbing:

- **Hero headline with editorial weight.** Default `serif` terminal at
  `size="xl"` or `"xxl"`, paired with a `Text` lede underneath at
  `size="l"`. The serif/sans alternation is the site's primary editorial
  signature.
- **Section header in product chrome.** `terminals="sans"` at `size="m"`
  or `"S"` for inline section headers — closer to UI text than to magazine
  layout. Use this in dashboards and the chat widget panel.

Anti-pattern to avoid: choosing the visual size first and letting the DOM
heading level fall out of it. Decide the semantic level (document outline)
first, then choose the visual size that fits the layout.

## How to use

```tsx
import Title from '@dt/Title';

// Hero h1 at largest serif size
<Title level={1} size="xxl">We design clarity.</Title>

// Section h2 in sans
<Title level={2} size="m" terminals="sans">Recent work</Title>

// Visual-only heading inside a card (no semantic level — use `as="span"`)
<Title as="span" size="s">Featured</Title>
```

Required consumer wiring: nothing. Title resolves typography tokens from
`variables.css` directly. The default tag is `h1`, so always pass `level`
or `as` when nesting inside a page that already has an h1.

Theme & forced-colors notes: colour is inherited from the parent surface
so light, dark, and forced-colors modes all work without per-component
overrides. The text follows the system colour in forced-colors mode.

## When to use

- The semantic heading for a page, section, card, or modal title.
- Visually-weighted display text that must scale with the typographic
  system (use a size variant rather than a one-off CSS override).
- Inside `Hero` / `Section` / `Card` patterns where the heading level is
  prescribed by the parent layout's outline rules.

## When not to use

- Body copy and supporting paragraphs — use **Text**.
- Form field labels — use **Label** (it carries the `htmlFor` association).
- A button label that happens to be large — use **Button** with the size
  prop and keep the semantics on the action.
- An inline emphasised phrase inside a paragraph — use `<Text as="strong">`.

## Accessibility

- **Outline:** the `level` prop maps directly to `h1`–`h6`. Consumers are
  responsible for keeping a single h1 per route and not skipping levels
  (h2 → h4). Title does not enforce outline rules; the page does.
- **Visual ≠ semantic:** size and level are independent. A visually small
  heading can still be `level={2}` if the outline demands it; a visually
  large display can be `as="span"` when no heading semantics apply.
- **Contrast:** colour inherits from the surface. Verify in dark mode and
  forced-colors mode in the **ForcedColors** and **Themes** stories.
- **Reduced motion:** Title is purely typographic. No motion to suppress.
