# Card

**Status:** beta · **Tier:** molecule · **Group:** structure

Composable surface for grouped content. Card carries an optional header
(title / subtitle / description / icon / badge / extra), a body slot that
accepts either a `body` string or arbitrary `children`, an optional cover
slot for media at the top, and a footer slot for actions. The component is
intentionally large because it absorbs the variation work — variants
(`elevated` / `filled` / `outlined`), sizes (`sm` / `md` / `lg` / `full`),
hoverable, bordered, loading, interactive, and link-rendered forms — so
that consumers don't fork it.

## In use

The canonical surface for `patterns/ServicesGrid`, `patterns/ProjectGrid`,
the article cards in `patterns/BlogIndex`, and the compliance panels in
`patterns/About`. Tabs-in-card composition is exercised in
`patterns/Pricing` where the same card hosts monthly / annual pricing
without re-mounting.

Three compositions worth cribbing:

- **Linked card.** Pass `link="/work/x"` and the entire surface becomes an
  anchor with `aria-label={linkLabel || title}`. Don't nest interactive
  controls inside this mode — anchor inside anchor is invalid.
- **Interactive card with click handler.** Pass `interactive` (or
  `onClick`) and the surface becomes a focusable element with Enter / Space
  activation. Use this when the action is *not* a navigation (e.g. open a
  modal, expand a panel).
- **Card with tabs.** Pass `tabs={[...]}` and the card hosts an internal
  `<Tabs />`. Bind `activeTabKey` for controlled mode or rely on
  `defaultActiveTabKey` for uncontrolled.

Anti-pattern to avoid: a card with both `link` and `actions`. The link
swallows the whole surface, so action buttons inside the footer become
unreachable. Pick one affordance per card.

## How to use

```tsx
import Card from '@dt/Card';

// Outlined service card
<Card
  variant="outlined"
  title="Design sprint"
  subTitle="One week, one prototype"
  description="A focused engagement to validate a hypothesis before committing roadmap."
  actions={[{ key: 'start', label: 'Start your sprint', variant: 'primary', onClick }]}
/>

// Linked project card with cover image
<Card
  link="/work/example"
  linkLabel="View Example case study"
  cover={<img src="/case.jpg" alt="" />}
  title="Example case study"
  description="Outcome-first writeup of the engagement."
/>

// Loading skeleton
<Card title="Loading…" loading />

// Card with tabs hosting different content panels
<Card
  title="Pricing"
  tabs={[{ key: 'monthly', label: 'Monthly' }, { key: 'annual', label: 'Annual' }]}
  defaultActiveTabKey="monthly"
  onTabChange={setPricingMode}
>
  {pricingPanel}
</Card>
```

Required consumer wiring: nothing. The component reads its tokens directly
from `variables.css`. The `loading` skeleton is internal — pass `loading`
and the body block is replaced by a `role="status"` skeleton with
`aria-busy="true"`.

Theme & forced-colors notes: variants use `--color-surface-*` for fills
and `--color-border` for outlines. Hoverable mode bumps elevation via
`--shadow-md`, which the forced-colors stylesheet replaces with a
`SystemHighlight` border so the affordance survives.

## When to use

- A grouped content block on a marketing or work surface.
- A link target that should *look* like a tile rather than an inline link.
- A focused panel inside a flow (settings, configuration, pricing).
- A loading placeholder for content that arrives async.

## When not to use

- A full-bleed banner — use **patterns/Hero** or **AlertBanner**.
- A list item — use **List** with a custom `renderItem`.
- A modal — use **Modal** when the content must steal focus and dim
  background.
- A simple key/value display — use **Stack** with **Title** and **Text**
  primitives; Card adds chrome that isn't worth it for one line of content.

## Accessibility

- **Roles:** `link` mode renders an `<a>`; `interactive` mode renders a
  `<div role="button" tabIndex={0}>` with Enter / Space activation. The
  default non-interactive card is a plain `<div>` with no role — semantics
  come from the headings inside.
- **Headings:** the `title` renders as `Title level={titleProps.level ?? 3}`
  so the consumer controls heading rank. Don't ship a page with multiple
  card titles at `level=1` — pick the right rank for the document outline.
- **Status messages:** `statusMessage` with `statusMessageProps.tone="error"`
  renders `role="alert"`; other tones use `role="status"`. The polite /
  assertive distinction follows the underlying ARIA contract.
- **Loading:** the skeleton has `role="status"`, `aria-busy="true"`, and a
  translated `aria-label` from `t('card.loading')`. Screen readers
  announce that the card is loading rather than reading empty content.
- **Tabs inside a card:** uses the same `<Tabs />` accessibility contract;
  the parent must still render the tab panels (see **Tabs** docs).

## Promotion notes

- Card is intentionally last in the atom queue because its prop surface is
  the widest in the system. Most other components only have to consider
  Card as a *container* — not as a composition partner.
- Stable promotion blockers: AT-tree snapshots for the four required
  stories, real-browser forced-colors run, and documented production
  consumers (the marketing services grid is the highest-traffic candidate).
- Known debt: `bodyStyle` and `headStyle` allow inline style overrides
  that bypass the token system. Flagged for removal in v2.0.0 — consumers
  should compose via `bodyProps.className` / `headStyle`-equivalent slot
  classes instead.
