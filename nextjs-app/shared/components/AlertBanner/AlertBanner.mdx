# AlertBanner

**Status:** beta · **Tier:** molecule · **Group:** feedback

Inline banner for persistent, page-level status messages. AlertBanner
encodes severity through both colour and icon (so colour is never the
sole signal), carries an optional title + description, and supports a
dismissable variant for non-critical messages. Four tones —
`info` / `success` / `warning` / `error` — map to system roles and
live-region politeness automatically.

## In use

Used on `/contact` for the GDPR notice, on `/blog` author pages for
the moderation notice, and inside the chat widget when the AI guard
trips. Toast is the right primitive for transient feedback; AlertBanner
is for messages that should stay until the user reads them.

Two compositions worth cribbing:

- **Title + description.** Pass both for a banner that reads as a small
  document. Description can be a node so links, lists, and inline
  formatting are all fine.
- **Dismissable info.** Pass `dismissible` + `onDismiss` for messages
  that should disappear once the user acknowledges them. Don't make
  errors dismissable — the user shouldn't be able to hide a blocking
  problem.

Anti-pattern to avoid: using AlertBanner for transient feedback that
should disappear on its own. The banner has no auto-dismiss because
"sit here until acknowledged" is its job. For success after a form
submit, use **Toast**.

## How to use

```tsx
import AlertBanner from '@dt/AlertBanner';

// Informational notice
<AlertBanner
  tone="info"
  title="GDPR data request"
  description="We process EU contact data under legitimate interest."
/>

// Dismissable success
<AlertBanner
  tone="success"
  title="Message sent"
  description="We'll get back to you within two business days."
  dismissible
  onDismiss={() => setBannerHidden(true)}
/>

// Error with rich description
<AlertBanner
  tone="error"
  title="Submission failed"
  description={<>Check the highlighted fields and try again.</>}
  aria-live="assertive"
/>
```

Required consumer wiring: nothing. The internal Title and Text
primitives are mounted automatically; the dismiss button is a tertiary
Button with `aria-label="Dismiss alert"`.

Theme & forced-colors notes: each tone uses
`--color-<tone>-surface` + `--color-<tone>-text` from `variables.css`.
Forced-colors mode replaces the tone surface with the system's
`Canvas` and keeps the icon as the sole signal — which is why the
icon is non-decorative (`ariaLabel={tone}`) rather than hidden.

## When to use

- A page-level message the user should read before scrolling away
  (cookie consent fallback, GDPR notice, scheduled maintenance).
- A persistent error or warning that explains why a flow is blocked.
- A success acknowledgement that should remain visible until dismissed.

## When not to use

- Transient confirmation ("Settings saved") — use **Toast**.
- Validation error tied to a specific field — use the field's
  `error` slot / **HelperText**.
- A modal interruption — use **Modal**.
- A small chip-style label — use **Badge**.

## Accessibility

- **Roles:** the wrapper is `role="status"` with a configurable
  `aria-live` (default `polite`). Errors and warnings should pass
  `aria-live="assertive"` so the user is interrupted.
- **Icon:** the leading icon carries `ariaLabel={tone}` so the AT user
  hears "info" / "success" / "warning" / "error" alongside the message.
  This is intentional double-encoding — colour alone fails WCAG 1.4.1.
- **Dismiss:** when `dismissible`, the trailing button is a tertiary
  Button with an explicit `aria-label="Dismiss alert"`. The button is
  in the tab sequence; the rest of the banner is not focusable.
- **Reduced motion:** the dismiss animation is suppressed under
  `prefers-reduced-motion: reduce` — the banner just disappears.
