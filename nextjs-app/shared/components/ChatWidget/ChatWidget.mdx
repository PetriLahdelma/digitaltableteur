# ChatWidget

**Status:** beta · **Tier:** organism · **Group:** conversational

Floating chat widget powered by Vercel AI SDK's `useChat` hook plus a
local reducer for the email-handoff workflow. ChatWidget is the
biggest single component in the system because it absorbs the chat
loop, the streamed message UI, the AI guardrail flags, and the
"compose a real email to Petri" flow without forking. The component
mounts globally via the site layout and toggles open / closed via
the ChatToggle.

## In use

Mounted in `app/layout.tsx` as a globally-available widget. The
toggle is the only entry point; conversations are persisted to
`localStorage` (key `dt-donny-chat-v2`, with `dt-donny-chat` as a
legacy fallback) so the user can reload the page without losing
context. The chat backend resolves per-host: local dev hits
`/api/chat`, production hits `https://www.digitaltableteur.com/api/chat`
(see `resolveChatApiEndpoint`).

Three compositions worth cribbing:

- **Default mount.** `<ChatWidget />` — no props needed. The widget
  reads its title and description from i18n and resolves its
  endpoint automatically.
- **Override endpoint.** Pass `endpoint` to point the widget at a
  staging or branch-preview chat backend. The override takes
  precedence over the env-resolved default.
- **Custom title.** Pass `title` and `description` to override the
  default i18n strings (for sales pages or partner contexts where the
  default branding doesn't fit).

Anti-pattern to avoid: mounting two ChatWidgets per page. The toggle
is a fixed-position floating element that would visually collide; the
storage key would also collide so the conversations would interleave.

## How to use

```tsx
import ChatWidget from '@dt/ChatWidget';

// Default global mount (already in app/layout.tsx)
<ChatWidget />

// With explicit endpoint (preview deployment)
<ChatWidget endpoint="https://preview-x.digitaltableteur.com/api/chat" />

// With overridden title / description
<ChatWidget
  title={t('chatPartnerTitle')}
  description={t('chatPartnerDescription')}
/>
```

Required consumer wiring: mount once per app. The widget mounts a
ChatToggle at the bottom-right of the viewport that opens the chat
panel.

Theme & forced-colors notes: the chat panel uses
`--color-surface-elevated` for the message area, with bubbles styled
per role (user → primary; assistant → muted). Forced-colors mode
keeps role distinction via border + text-weight rather than
background colour so the contract holds without the surface fill.

## When to use

- A persistent, site-wide AI assistant for visitor questions.
- A floating support entry point that doesn't take up layout space
  unless the user opens it.
- An onboarding tour entry point ("Hi — want me to show you around?").

## When not to use

- A page-specific chat (e.g. one chat per article) — that pattern
  isn't built; use a fresh component if needed.
- A user-to-user chat — ChatWidget is single-channel to an AI; for
  multi-party chat use a real chat infra.
- A modal-style "ask one question" interaction — use Modal with a
  TextArea inside.
- A search-bar replacement — use the search pattern; ChatWidget's
  conversational latency is wrong for "find me this page".

## Accessibility

- **Toggle:** the ChatToggle is a Button with explicit `aria-label`
  and `aria-expanded` reflecting open / closed state. Keyboard users
  can reach it via Tab from the page; Enter / Space toggles.
- **Panel:** when open, the panel is rendered as a section labelled
  by the title. Focus does **not** auto-move into the input — the
  toggle stays the focused control until the user Tabs in, which
  matches expected non-modal-dialog behaviour. (The panel is not a
  Modal — content behind remains operable.)
- **Streaming messages:** assistant messages arrive incrementally.
  The message list is wrapped in a `role="log"` with
  `aria-live="polite"` so the AT user hears new content without
  jumping focus. `aria-atomic="false"` so only the new chunk
  announces, not the whole conversation.
- **Email workflow:** the email-compose sub-flow (when the AI
  hands off to "send Petri an email") uses an internal Modal-style
  review step. The reducer-driven flow has explicit focus
  management between Compose → Field → Review → Send states.
- **Keyboard:** Escape closes the panel. The composer accepts
  Enter to submit and Shift+Enter for a newline.

## Promotion notes

- ChatWidget gates the lowest-friction visitor interaction on the
  site, so promoting it to stable carries real conversion stakes.
  Stable promotion blockers:
  - AT-tree snapshots for closed / open / streaming / email-workflow
    states.
  - Forced-colors verification of every sub-component.
  - Manual screen-reader walkthrough of a full conversation +
    email handoff, captured in
    `ChatWidget.contract.json#a11y.screenReaderNote`.
  - Documented production consumer (`app/layout.tsx` is the
    canonical use).
- Known debt: streaming message announcements can clip when the
  AI emits very fast tokens — the polite live region debounces in
  hardware, which is sometimes visible as "every fifth chunk gets
  announced". Investigate switching to a Speech queue model in v2.
