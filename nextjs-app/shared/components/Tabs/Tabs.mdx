# Tabs

**Status:** beta · **Tier:** molecule · **Group:** navigation

Tablist with full ARIA Authoring Practices keyboard support. Tabs renders
only the tab strip — the parent is responsible for rendering the
matching tabpanels. Use the exported `getTabPanelProps(key, isActive)`
helper to wire the panel side without remembering the four required
attributes. Three visual variants (`default`, `pills`, `underline`) and
three sizes (`sm` / `md` / `lg`) cover the consumer surface.

## In use

Used inside `Card` (see the Pricing card composition), at the top of the
profile flows, and inside the contact form to switch between Personal
and Company message types. The CV page also uses Tabs to switch between
the rendered CV and the source markdown.

Two compositions worth cribbing:

- **Controlled with state.** Pass `activeTab` and `onTabChange` to drive
  selection from the parent. The component then becomes pure — internal
  state is bypassed.
- **Uncontrolled with default.** Pass `defaultActiveTab` and skip
  `activeTab`. The component manages selection internally and still
  fires `onTabChange` for analytics.

Anti-pattern to avoid: rendering only the active tabpanel without an
`aria-controls` link from the tab. Use `getTabPanelProps` — it produces
the right `id`, `role`, `aria-labelledby`, `hidden`, and `tabIndex` so
the contract holds.

## How to use

```tsx
import Tabs, { getTabPanelProps } from '@dt/Tabs';

const tabs = [
  { key: 'overview', label: 'Overview' },
  { key: 'pricing', label: 'Pricing' },
  { key: 'faq', label: 'FAQ' },
];

const [active, setActive] = useState('overview');

<>
  <Tabs
    tabs={tabs}
    activeTab={active}
    onTabChange={setActive}
    variant="underline"
    size="md"
  />
  {tabs.map((tab) => (
    <div key={tab.key} {...getTabPanelProps(tab.key, tab.key === active)}>
      {tab.key === active && <Content for={tab.key} />}
    </div>
  ))}
</>
```

Required consumer wiring: render the tabpanels with `getTabPanelProps`,
or hand-spread `{ id: 'tabpanel-<key>', role: 'tabpanel',
'aria-labelledby': 'tab-<key>', hidden: !isActive, tabIndex: isActive ? 0 : -1 }`.

Theme & forced-colors notes: the underline variant uses
`--color-primary` for the active indicator. Forced-colors substitutes
`Highlight` and falls back to a bold-weight text treatment in case the
indicator is hidden by the system stylesheet.

## When to use

- Sibling content panels where exactly one is visible at a time.
- Multi-step forms where the user can revisit any step.
- A switcher between alternate views of the same data (Monthly /
  Annual pricing, Day / Week / Month calendar).

## When not to use

- Top-level site navigation — use **patterns/SiteHeader**.
- A two-state toggle — use **Switch**.
- A linear flow where step order matters — use a stepper component;
  Tabs lets the user jump between steps in any order.
- A picker for a value that doesn't reveal a panel — use **Select**.

## Accessibility

- **Roles:** the wrapper is `role="tablist"`; each tab is
  `role="tab"` with `aria-selected` / `aria-controls`. Panels (rendered
  by the parent) must be `role="tabpanel"` with `aria-labelledby`
  pointing back to the tab id.
- **Keyboard:** ArrowLeft / ArrowUp moves selection to the previous tab,
  ArrowRight / ArrowDown to the next. Home jumps to the first, End to
  the last. Enter and Space activate the focused tab. Disabled tabs are
  skipped by arrow keys and reject Enter / Space.
- **Roving tabindex:** the active tab has `tabIndex={0}`; the rest have
  `tabIndex={-1}` so Tab moves focus *out* of the tablist (into the
  panel), matching APG behaviour.
- **Wrap-around:** Arrow keys wrap (first ⇄ last). Disabled tabs are
  visible in DOM but skipped by the focus logic.

## Promotion notes

- Tabs gates Card's pricing-tab composition, so promotion here unblocks
  several downstream consumers.
- Stable promotion blockers: AT-tree snapshots for the four required
  stories (default / pills / underline / disabled), forced-colors run,
  and documented production consumers (CV page and pricing card).
- Known debt: there is no `orientation="vertical"` support yet. Vertical
  tabs need a different arrow-key contract (Up/Down primary) and a
  visual variant; deferred until a real consumer asks.
