# EngagementPageContent

## Intent
One offer page per engagement (Design System Audit, Lift-Off, AI-Ready Ops, Embedded partnership), so a buyer sees scope, limits, steps, deliverables, price, proof and the next step before getting in touch.

## Interaction contract
- Keyboard: calls to action, links and FAQ triggers in reading order
- Screen readers: one h1 per page; a labelled breadcrumb landmark leads it; each section labelled by its h2; steps are an ordered list; each other-engagement row is one link carrying name, timeline and price

## Do / don't
- Do: take every claim from published sources (package data, the service catalog, project data)
- Do: read prices from the pricing page keys so a price changes in one place
- Do: keep the breadcrumb trail identical to the BreadcrumbList structured data (Home / Pricing / engagement)
- Don't: repeat a procurement question in the offer FAQ
- Don't: list the current engagement among the other engagements
