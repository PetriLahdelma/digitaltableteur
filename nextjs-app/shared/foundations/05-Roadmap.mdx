# Roadmap

Design system foundations and maturity — **Storybook is the catalog of record**.
Numbers below are read from `agent-manifest.json` and `token-catalog.json`; the
gates that keep them honest are named next to each claim.

## Catalog & maturity (current)

The headline number is the **catalog** count, not every component-shaped folder
in the tree. `npm run audit:catalog` reports **204 catalog entries** and
**166 governed** (contract-bearing) components, for **90.2% catalog
completeness** — declared under `summary.catalogCompletenessPercent` so AI
consumers don't read the contract list as the whole front-end.

| Dimension | Today |
|-----------|-------|
| Governed components | 166 (204 catalog entries) |
| Catalog completeness | 90.2% |
| Status mix | **98 stable · 44 beta · 23 alpha · 1 deprecated** |
| Tests | 2732 passing / 333 files, 0 failing |
| A11y-tree snapshots | 122 components carry committed `__a11y-snapshots__/` |

Reproduce: `npm run audit:catalog` (CLI) or
`node scripts/design-system/audit-catalog-coverage.mjs --json` (manifest).

## Quality gates (mechanised)

The stable tier is real: promotion to `status: "stable"` is gated on committed
evidence, not template presence.

| Gate | State |
|------|-------|
| A11y-tree snapshots | Committed per stable component under `__a11y-snapshots__/`; captured via `DT_UPDATE_A11Y_SNAPSHOTS=1 npm run test:stories:ci` |
| Real-browser forced-colors | `npm run test:stories:hc` per required story |
| Light/dark visual baselines | `npm run test:visual` baselines per theme |
| Doc semantics | RFC 2119 guideline levels, `docOrigin`, a11y `verificationMode`, `governance.lastReviewed` — gated by `check:doc-semantics` |
| Contract ↔ props parity | `check:contract-props` — beta/stable props match agent blocks |
| Token discipline | `check:tokens` (color), `check:radius-shadow` (radius + elevation), stylelint baseline |

## npm consumption

Four packages publish to the registry and are consumed back into this repo
(the dogfooding mandate): `@digitaltableteur/react`,
`@digitaltableteur/web-components`, `@digitaltableteur/tokens`, and
`@digitaltableteur/tokens-css`. Strict runtime dogfooding is partial by design:
`npm run report:component-usage` currently reports 33/166 imported directly from
`@digitaltableteur/react` and 68/166 rendered in production transitively.

## Open work (honest)

Not everything is closed. The live gaps:

- **`app/**` site CSS** still has naked `border-radius` outside the design-system
  scope covered by `check:radius-shadow`.
- **Runtime dogfooding** — 33/166 direct registry imports; raising this is the
  standing consumption mandate, one component per PR.
- **Native web-component `implementationA11y`** is captured but not yet enforced
  as a gate.
- **Consumers manifest drift** — a handful of shell components (SiteHeader,
  Logo, SiteFooter, …) report `consumers-drift`; run `npm run audit:consumers`.

## Not planned (by design)

- Importing `foundations/dist/tokens.css` at runtime (see ADR-0004)
- Copying external palette or spacing literals into this repo (see ADR-0005)

## Commands

```bash
npm run build:tokens         # catalog + DTCG + dist + Tailwind bridge + agent manifest
npm run check:contrast       # WCAG AA semantic pairs
npm run check:radius-shadow  # radius + elevation token discipline
npm run validate:components  # all component gates
npm run audit:catalog        # codebase vs catalog completeness (90.2% today)
npm run report:component-usage  # runtime dogfooding coverage
```
