## Honest Beta (Phase 1 — closed)

The previous "27/27 beta" claim was cosmetic: contracts were tagged `status: "beta"`
but their MDX was scaffolder boilerplate and their `spec.md` was a `TODO:` template.
The validator passed because the gates checked for *presence* of headings, not real
prose. This milestone made "beta" mean what the contract says it means.

## Honest catalog coverage (the breadth overclaim, walked back)

The headline "100 components" number is the **catalog** count, not the
**codebase** count. `npm run audit:catalog` walks
`nextjs-app/shared/{components,patterns}` and finds **179** component-shaped
folders — meaning a folder owning a same-named `.tsx` file. Of those:

| Bucket | Count | Decision |
|--------|------:|----------|
| **In catalog** (`contract.json` present) | 100 | The number we report everywhere else |
| **Catalog gap** (atoms/molecules that *should* be in the catalog) | 25 | Phase-2 work — being scaffolded now |
| **Page pattern** (page-level assembly, judgement call whether to catalog) | 31 | Phase-3 work — pattern policy first |
| **Enhanced / editorial fork** (uncataloged variant of a cataloged component) | 6 | Reconcile with parent or document as a deliberate fork |
| **Bespoke / infrastructure** (utilities like `Toaster`, `Mermaid`, error boundaries) | 17 | Exempt from the catalog by design |

So the **honest catalog completeness is 55.9% (100/179)**. The agent manifest
declares this under `summary.catalogCompletenessPercent` so AI consumers don't
read the contract list as if it were the whole front-end.

Audit reproducible: `npm run audit:catalog` (CLI) or
`node scripts/design-system/audit-catalog-coverage.mjs --json` (manifest).

## Honest comparison to DSharp (the parity overclaim, walked back)

Earlier roadmap drafts implied near-parity with DSharp. That was overstated.
A breadth-only comparison reads close, but maturity gates and tooling do not.

| Dimension | Digitaltableteur (today) | DSharp (reference) |
|-----------|--------------------------|--------------------|
| Contract count | 100 in catalog out of 179 component-shaped folders in the codebase (55.9% catalog completeness) | 112 |
| Status mix | 27 beta / 73 alpha / **0 stable** | 110 beta / **2 stable** |
| Parity scoring | Phase-1 story presence only (per `parity-audit.mjs` line 1) | zod catalog, agent evals, beta/SR debt checks, size budgets, dark/HC/viewport/story/visual/a11y snapshot CI (`package.json` line 34) |
| Public import path | `@dt/<Component>` aliased at the workspace root; no documented subpath/export policy | Versioned package surface with semver guarantees |
| Figma references | Placeholder `figma.nodeId` strings | Real node IDs verified by `figma-mcp` |
| AI manifest | Generated; no zod schema validation, no eval suite, no a11y/visual gates | zod-validated; agent eval suite; gates fail CI on regressions |

Breadth is close, **maturity is not**, and even breadth is overstated unless
the catalog-gap bucket lands. The next phase below is the work that closes
the gap, not the celebration that it's already closed.

## Stable-tier prerequisites (Phase 2 — not yet started)

The maturity gates below have to be **mechanised** before promoting anything
to `status: "stable"`. Each one is a content-or-CI gap, not a contract
template gap.

| Gate | Current | Required at stable | Owner |
|------|---------|--------------------|-------|
| A11y-tree snapshots | 0 committed | `DT_UPDATE_A11Y_SNAPSHOTS=1 npm run test:stories:ci` per beta component, snapshots committed under `__a11y-snapshots__/` | Design system |
| Real-browser forced-colors | 28 hand-asserted | `npm run test:stories:hc` per required story, PNG diffs committed | Design system |
| Production consumers | 0 documented | Auto-detect script populates `<Component>.contract.json#consumers[]` from `app/**` grep | Design system |
| Light/dark visual baselines | 0 committed | `npm run test:visual` baselines per beta component, per theme | Design system |
| Manual SR walkthrough (optional) | Mostly empty | `a11y.screenReaderNote` filled per beta component for the promotion ceremony | Design system |
| Catalog-gap migration | 25 atoms/molecules outside the catalog (per `npm run audit:catalog`) | Each one has a `contract.json`, `stories.tsx`, `mdx`, `spec.md` | Design system |
| Page-pattern policy | 31 page-level assemblies undeclared | A written policy on whether page-level patterns enter the catalog, with the 31 folders triaged against it | Design system |
| `npm run test:ci` | 53 files / 197 tests failing (2026-05-26) | 0 failing — real test rot triaged + legacy Vite trees deleted | Engineering |
| Bundle-size budgets | None | `size-limit` configured per public entrypoint, enforced in CI | Engineering |
| Agent-manifest schema | Hand-written | `zod` schema in `scripts/design-system/agent-manifest.schema.ts` validates every build | Design system + AI |
| Agent eval suite | None | A small set of prompt-rendered-task evals (e.g. "build a contact form using only `@dt` components") with golden snapshots | Design system + AI |
| Real Figma node refs | Placeholder strings | `npm run figma:link` resolves every `figma.nodeId` against the team library | Design |

The validator already gates the first four at `status: "stable"` — the
gap is the *content* and the *new gates*, not the existing infrastructure.
