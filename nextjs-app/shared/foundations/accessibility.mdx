## What stable means

A component reaches the stable tier only with evidence committed next to it: an axe test, accessibility-tree snapshots, a forced-colours check and a dated review note in its contract. Templates and good intentions do not count. Beta and alpha components can be used, but read their contract before you rely on them for a key flow.

## What you still own

The components handle their own semantics. The page around them is yours.

- Give every icon-only button an accessible name. A tooltip is not a name.
- Keep one h1 per page and do not skip heading levels. Pick the heading level for the outline and the size for the look.
- Write alt text that says what the image is for, or mark it decorative.
- Make link text make sense on its own. “Read more” next to five cards is five identical links.
- Ship every user-facing string in English, Finnish and Swedish, and set the page language.
- Never remove a focus style. Restyle it with the focus tokens instead.
- Do not use colour as the only signal. Pair status colours with text or an icon.

## Check your work

Run these before you open a pull request. The first two take seconds.

```bash
npm test                     # component tests, axe included
npm run check:contrast       # semantic colour pairs in all four themes
npm run test:stories:hc      # stories under forced colours in a real browser
npm run test:a11y:pages      # page-level checks on the site
```
