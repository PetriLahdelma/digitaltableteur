## The contract

Each component folder holds a `<Name>.contract.json`, validated against `scripts/design-system/contract.schema.v2.json`. Unknown keys are errors, and every contract carries a `schemaVersion` so it can be migrated.

Most of these run in the pre-push hook, so the local gate catches drift before anything reaches a pull request.

## Rules agents can check

When a component already detects an invalid prop combination at runtime, the contract records it as a `forbiddenCombos` rule, with the condition, what it forbids or requires, a severity and the evidence. `validate:agent-usage` then checks every call site against those rules, so a combination that only warned in the console now fails the check.

## For agents

The schema, the generated `agent-manifest.json` and `docs-registry.json` in `nextjs-app/shared/foundations/dist/` are the authoritative inputs for generating or changing a component. Generate against the schema; the gates above verify the result. See [Agent readiness](?path=/docs/overview-agent-readiness--docs) for the tools that read them.
